This is the decisive finding. `src/secret_storage.py:34` has `_fernet: Fernet | None = None` — a **module-level variable annotation** using PEP 604 union syntax, with **no `from __future__ import annotations`**. ## ⚠️ SINGLE MOST LIKELY THING TO BREAK on Python 3.9.6 / Apple Silicon

**Two traps, ranked:**

1. **(HARD CRASH — the real blocker) PEP 604 union at module scope on Python 3.9.** `src/secret_storage.py:34`:
   ```python
   _fernet: Fernet | None = None
   ```
   This is a **module-level variable annotation evaluated at import time**, and the file has **no `from __future__ import annotations`**. On Python 3.9.6, `Fernet | None` raises `TypeError: unsupported operand type(s) for |: 'type' and 'NoneType'` the moment `app.py` imports it. The app cannot start under 3.9.6, full stop.
   **Dodge:** build the venv with Python **3.11+** (3.11/3.12/3.13). Never run `python3 app.py` / `python3 -m uvicorn` with the system `/usr/bin/python3` (3.9.6). `start-macos.sh` and `setup.py:check_arch()` enforce this for you — use them.

2. **(WRONG-ARCH CRASH) Intel/Rosetta Python building the venv on Apple Silicon.** A universal2 or x86 Python (python.org installer at `/usr/local`, or anything under Rosetta) builds a venv whose compiled wheels (`bcrypt`, `pydantic-core`, `onnxruntime`, `cryptography`) load as the wrong arch → `"(mach-o file, but is an incompatible architecture)"` deep inside an import. `setup.py:check_arch()` (`setup.py`, the `check_arch` function) detects this and aborts with guidance; `start-macos.sh:74-84` only accepts `/opt/homebrew` arm64 Python.
   **Dodge:** always create the venv with `/opt/homebrew/bin/python3.11` (arm64). If you hit it: `rm -rf venv && /opt/homebrew/bin/python3.11 -m venv venv && ./venv/bin/pip install -r requirements.txt`.

**Secondary gotcha (handled, but know it):** `requirements.txt` pins **`chromadb-client`** (HTTP-only), which conflicts with the embedded `chromadb` the native path needs. `start-macos.sh:150-157` auto-uninstalls it and force-reinstalls full `chromadb`. If you do the manual fallback, run the uninstall/reinstall line yourself (README:308-309) or RAG silently fails in HTTP-only mode.
